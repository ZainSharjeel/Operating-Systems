Q3a: As discussed in Remzi book there are many benefits of pipes over other file redirection methods. Pipes allow real-time communication between processes. When one process writes data into the pipe, another process can read it immediately. This enables the creation of a chain of processes where data flows directly from one to another, often seen in UNIX pipelines. This real-time flow of data is typically not achievable with file redirection, where data would first need to be written to a file and then read back. Unlike file redirection, which requires a physical file to store the data temporarily, pipes operate entirely in memory. This means faster data transfer and no risk of exhausting disk space with large temporary files. Pipes are more efficient than file-based communication because they eliminate the overhead of file I/O. Writing and reading directly from memory in the case of pipes is much faster than writing to and reading from disk. Pipes manage their own buffering automatically. When data is written into a pipe, it remains there until it is read. File redirection, on the other hand, often involves explicitly handling file opening, writing, closing, and reopening for reading. Pipes are well-suited for stream-oriented processing, where data flows continuously, like logs or real-time data processing. File redirection typically works on a file-by-file basis, which is less efficient for handling streams of data. Pipes provide a simple and effective way to implement IPC between related processes. In contrast, file redirection is not an ideal mechanism for IPC since it lacks synchronization mechanisms that pipes offer inherently.
